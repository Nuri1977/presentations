A write

Files first, then one commit

1
Write Parquet files
New rows go into new files in the data folder. Not visible yet.
2
One transaction in the catalog
It records the files and creates a snapshot. Now the change is visible.
3
If anything fails
The catalog does not change. Readers never see half a write.

A read

Ask the catalog, then read less

1
Which files are the table now?
The catalog answers with a list of files.
2
Skip files by statistics

3

Only the Parquet files that can match.

What this design gives you

Three things for free

Safe changes
Real transactions
All or nothing, even across several tables.
History
Snapshots and time travel
Query a table as it was yesterday, or last week.
Small changes
Stay small
A few rows in the catalog, not a pile of metadata files.
