You write a select. That's a model.

select customer_id, count(*) as order_count from raw.orders group by customer_id
)
you write this dbt adds the orange lines

Know the boundaries

What dbt does not do

dbt does not

✗Extract data from source systemsEL tool
✗Load raw data into the warehouseEL tool
✗Store data or run queries itselfyour warehouse

dbt does

✓Writes the SQL
✓Orders it by dependency
✓Adds the engineering around it
What dbt adds

The engineering is the real value

Testing

Tests run on every build.

Documentation

Generated from the code.

Version control

Everything in Git, every change reviewed.

In short

Software engineering practice, for SQL

dbt in one sentence dbt compiles SQL select statements and Jinja into runnable code, executes it in dependency order inside your data platform, and adds testing, documentation and lineage.
Analogydbt is to SQL what a build system is to source code.
