ROSETTA DBT STUDIO — JAFFLE SHOP ANALYTICS
PHASE 1 SLIDE NARRATION
Deck: presentation-slides.html

Audience: people using dbt models to create and share an Analytics page.
Promise: Show the finished Jaffle Shop report, then how AI assistance in
Rosetta DBT Studio led to a static site saved inside the dbt project.

Slide 1 — The Jaffle Shop Analytics page
Visual: slide-01-browser-report-overview.png
Narration:
"Here is the finished Jaffle Shop Analytics page. It brings order measures,
a daily revenue chart, and an orders-by-status chart into one report. The page
was developed in Rosetta DBT Studio with help from the AI assistant. Now I'll
show how it was exported into the dbt project."

Slide 2 — The AI assistant helped build and correct the page
Visual: slide-02-studio-ai-analytics.png
Narration:
"Inside the SQL Analytics tab, the page combines named SQL queries with the
components that display their results. The assistant helped write and run the
page, then corrected a date display issue visible in the conversation. We
review the SQL and the rendered charts before publishing."

Slide 3 — Build a static Analytics site
Visual: slide-03-studio-build-dialog.png
Narration:
"Once the page is ready, we open Build Analytics Site. Rosetta runs the page
queries and includes the returned data in the output. This creates a report
that can open in a browser without a live database connection. Its values are
a snapshot from the time of the build."

Slide 4 — Save the export inside the dbt project
Visual: slide-04-choose-project-folder.png
Narration:
"For this demo, we choose the analytics-page folder inside the
rosetta_studio_analytics_demo project. This is the export destination. The
editable Analytics page is still stored in Studio; the static website files
are what we save alongside the dbt project."

Slide 5 — The project contains the exported report
Visual: slide-05-project-export-preview.png
Narration:
"After the build, the project Explorer shows analytics-page with index.html,
a pages folder, and the site assets. We can open the index in Studio and preview
the generated site. That gives us a concrete artifact to keep or share with
the project."

Slide 6 — Verify the browser output
Visual: slide-06-browser-report-insights.png
Narration:
"Finally, we open the generated report in a browser and check more than the
headline numbers. The page shows the payment-method breakdown and the recent
orders table, with the query results embedded in the export. That completes
Phase 1: an AI-assisted Analytics page and a static report saved inside the dbt
project."

ARCHITECTURE INTERLUDE — BETWEEN PHASE 1 AND THE LIVE VIDEO

Slide 7 — One screen: editor, preview, assistant
Visual: slide-07-studio-markdown-preview-ai.png
Narration:
"Before the live video, let's look behind the Analytics screen. The Markdown
editor is on the left, the page preview is in the middle, and the AI assistant
is on the right. We can see the page source, its rendered result, and the
assistant's work together. The history includes failed query attempts, so we
check status and results rather than assuming every suggestion worked."

Slide 8 — Write the page yourself or with AI assistance
Visual: slide-08-studio-markdown-editor-ai.png
Narration:
"A page starts as Markdown. We add headings, named SQL blocks, and component
tags such as BigValue and BarChart. You can write those directly. In Code mode,
the assistant can inspect the active page, edit it, run queries, and review
their results. The layout preview responds to editing, but SQL runs when we
run a query or select Run All."

Slide 9 — From Markdown to a live chart
Visual: four-step architecture on a light background.
Narration:
"The editor content is parsed into text, named queries, and components.
When we run the page, the query engine orders any dependencies and sends SQL
to the selected database connection. Results return under their query names;
the renderer passes those rows to KPI cards, charts, and tables. Studio saves
the editable page in its application database. A site build separately writes
HTML with results captured at build time."

Slide 10 — Choose a component, bind a query result
Visual: named SQL example and selected component groups.
Narration:
"Here is the smallest example: a named total-orders query returns a row, and
BigValue displays its order count. The same page can use LineChart for a trend,
BarChart or DonutChart for comparisons, and DataTable for details. Layout
components arrange those views, and input components are available when the
page needs controls. This is the authoring model behind the report we just
opened."

Slide 11 — What the Analytics agent can use
Visual: slide-11-studio-analytics-agent-context.png beside the page, database,
project, and optional extension context.
Narration:
"The Analytics assistant has tools that connect its work to the real page and
data. It can read the active page, inspect the selected database schema and
query results, and in Code mode edit and run the page. When a dbt project is
linked, it can also read its models and files. Imported skills and connected
MCP servers can add specialized guidance and tools. Agent Memory can provide
longer-term context when it is enabled and initialized. We still check the
query output and preview before sharing the result. Next, the separate live
video will show a new Analytics page being created."
