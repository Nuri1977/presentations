Chapter 02

Visual and YAML authoring

Both modes operate on one pipeline draft. Visual mode is a structured projection; YAML mode is the lossless text escape hatch.

parsePipelineConfig parses YAML and validates the shared shape
PipelineView projects jobs and steps into graph nodes and edges

Graph semantics

Nodes and edges

Steps become nodes. Steps in one job connect sequentially; dashed edges mark job boundaries. Cleanup styling derives from job.type: cleanup.

Stable serialization

Connected nodes use topological order. Disconnected nodes use canvas X position. Consecutive nodes with the same job name become one YAML job.

Validation

Visual save rejects empty graphs, cycles, unnamed steps, and missing plugin-specific fields.

Undo and redo

Each edit session keeps bounded snapshots of nodes, edges, and pipeline name. A new mutation clears future history.

Draft safety

Switching views or running with visual changes requires Save, Discard, or Cancel. Disk refresh updates a clean tab, but a dirty draft stays in memory and offers Reload from disk or Keep my draft.

Loss prevention: unknown fields remain editable in YAML. Visual editing is disabled with bounded diagnostics when it cannot guarantee a lossless round trip.
