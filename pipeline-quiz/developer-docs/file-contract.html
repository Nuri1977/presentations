Chapter 03

Files and discovery

Pipeline identity is project-relative and nested. The current root wins, while the former root remains readable for compatibility.

rosetta/pipelines/legacy .rosetta/.yml + .yaml

Discovery rules

RuleBehavior
Canonical rootNew built-in, community, selector-fallback, and Agent-created files use rosetta/pipelines/.
Legacy root.rosetta/ stays recursively readable and updateable.
ExtensionsBoth .yml and .yaml are recognized.
Exclusionmain.conf is never a pipeline.
Identityquality/nightly.yml becomes quality/nightly.
CollisionThe canonical path wins over the same legacy identity.

Minimum schema

name: "Full CI/CD"
jobs:
  - name: "build"
    steps:
      - name: Run models
        plugin: dbt@v1
        command: dbt run
        working_dir: dbt

The root requires a string name and jobs array. Every job requires a name and steps array. Every step requires a name and plugin. Malformed YAML or invalid structure returns null rather than reaching the graph renderer.

Creation paths

Explorer modal

Creates Blank or Generic templates, nested folders, and community templates. It confirms before replacing an existing destination.

Selector fallback

Can create pipeline.yml. Cloud mode may stage, commit, and push; Local mode skips Git requirements.

Community template boundary: the main process restricts downloads to trusted raw GitHub URLs, but fetched YAML is written before schema parsing. Treat it as executable input requiring review.
