Chapter 05

Rosetta Cloud

Cloud execution is a remote-Git workflow. DBT Studio sends repository identity and run configuration; it does not upload the local working tree.

rosettaCloud:*remote Git source3-second polling

Preconditions

  • Selected project with a Git repository and HTTP(S) remote ending in .git
  • Current branch exists on the remote
  • Selected pipeline is not dirty, staged, untracked, or unpushed
  • Profile variable metadata is loaded and Cloud authentication exists
  • dbt Core v2 is not selected because Cloud does not currently support it

Request contract

{
  id, title, gitUrl, gitBranch, secrets,
  EXECUTION_MODE: "pipeline",
  PIPELINE_FILE: "quality/nightly.yml",
  ROSETTA_RUN_TEARDOWN: true | false
}

CUSTOM_DBT_COMMANDS is omitted in pipeline mode. Nested relative paths remain part of the Cloud identity.

Main-process orchestration

Create or resolve the Cloud project from title, URL, and branch
Update local externalId when Cloud identity differs
Upload edited required secrets and custom variables
Start a pipeline-mode run with teardown preference
Persist the returned or resolved action ID by pipeline filename

Status and logs

Status and logs poll every three seconds while active. Overall action status decides completion when present; step states are the compatibility fallback. Logs support ANSI formatting, safe HTML escaping, timestamps, wrap, copy, clear, minimize, and fullscreen.

Known limits: fallback searches only the newest 20 actions. Step-to-node mapping uses step names. The current manual handoff can normalize .yaml to .yml.
