Chapter 06

Project Agent pipeline tools

Pipeline authoring belongs to the existing Project Agent. There is no pipeline screen key and no separate Pipeline Agent factory on dev.

Ask: list + readCode: generate + updatepersisted files only

Tool surface

ToolPurposeMode
studio_pipeline_listReturn bounded canonical and legacy pipeline identities.Ask + Code
studio_pipeline_readRead one contained file and return its SHA-256 content hash.Ask + Code
studio_pipeline_generateCreate validated YAML under the canonical root.Code
studio_pipeline_updateReplace an existing pipeline when the expected hash still matches.Code

Safe update flow

List returns project-relative contained paths
Read returns content plus trusted hash
Update compares expected hash to current bytes
Shared YAML/Zod and plugin contracts validate proposed content
Sibling temporary file is replaced, then persisted content is revalidated
Renderer refreshes Explorer, Git, selector, and clean editor state

Containment and rollback

Rejected targets

Absolute paths, traversal, symlinks, paths outside supported roots, and non-YAML extensions fail closed. Generic file/model tools reject pipeline targets.

Discard behavior

Existing files restore from the first pre-write snapshot, with Git as fallback. New files are removed and their tabs close.

Hard boundary: these tools do not run Local Runner, request Cloud runs, read Cloud status/logs, commit, push, or edit an unsaved live pipeline draft.

Two catalogs

src/shared/pipelinePluginCatalog.ts provides serializable validation context used by backend Agent tools. pipelineView/pluginDefinitions.ts owns renderer-only palette icons and editor metadata. Do not collapse those responsibilities.
