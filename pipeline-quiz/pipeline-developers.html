Authoring lifecycle

From file click to persisted YAML

A recognized pipeline never opens as an ordinary file tab. It becomes a virtual pipeline workspace that projects one canonical draft into two editing modes.

01

Recognize

Any nested .yml or .yaml below rosetta/pipelines or legacy .rosetta is treated as a pipeline.

02

Parse

js-yaml and Zod check the root, jobs, steps, names, and plugins. Invalid input returns null safely.

03

Project

PipelineView turns valid YAML into React Flow nodes and edges. Unsupported fields keep Visual mode read-only.

04

Edit

Visual edits serialize back to YAML. YAML mode edits the same draft. Dirty transitions require an explicit decision.

05

Persist

The project save path writes the file, then refreshes Explorer, Git status, and clean editor content.

Persistence contract

Canonical paths and stable identities

Discovery rules

  • New files belong under rosetta/pipelines/.
  • Legacy .rosetta/ remains recursively readable.
  • Only .yml and .yaml are included.
  • main.conf is always excluded.
  • Identity is the nested POSIX path without extension.
  • Canonical files win over duplicate legacy identities.

Minimum valid shape

name: string
jobs:
  - name: string
    steps:
      - name: string
        plugin: string

Optional fields include job type, command, working directory, and git-clone fields. Unknown fields are preserved in YAML but can disable Visual editing to prevent lossy serialization.

Visual graph semantics

Steps within a job are sequential. Dashed edges cross job boundaries. Cleanup comes from job.type: cleanup. Serialization topologically orders connected nodes and uses X position for disconnected nodes.

  • Reject empty graphs and cycles
  • Require step names and plugin fields
  • Snapshot nodes, edges, and name for undo/redo

Known edge cases

Manual Cloud handoff currently reconstructs a .yml name after stripping either extension, so it does not preserve .yaml exactly. Cloud status maps steps by name, making duplicate step names ambiguous. Action fallback scans only the newest 20 actions.

Safety boundaries

Mutation is deliberate

Unsaved UI drafts

Switching mode or running prompts Save, Discard, or Cancel. Clean disk refreshes never overwrite a dirty draft without a choice.

Agent stale-write protection

Updates require the SHA-256 hash from a preceding read. Writes are contained, reject symlinks/traversal, validate before and after replacement, and never commit or run.

Cloud source of truth

Cloud clones the configured remote branch. Dirty or unpushed selected pipeline files block the Cloud selector because local bytes are not uploaded.

Credential ownership

Secrets and binary paths are resolved by trusted main-process code. The renderer supplies identities and user choices, not arbitrary executables.
